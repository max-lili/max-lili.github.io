从一个想法出发，策划成方案、做成能双击运行的互动网页、再产出可上架发社媒的全套物料。覆盖三个 skill 及把它们串起来的总控。

02快速上手：一条龙跑通

如果想一次性做完，直接在对话里说：

做一整套测评产品，主题是"恋人类型测评"，目标人群是 18-30 岁女生，
规模用标准档，风格甜暖治愈，商用，口令用 3167。

触发总控后，会自动完成：

  1. 统一澄清：上面没说的（如引流题数量、视觉细节）用默认值并注明，不再反复追问。
  2. 出策划案：八章结构，去侵权处理。
  3. 做网页：口令固定为 3167，做完浏览器实测。
  4. 出物料：封面、引流卡片、文案、发货文案；没给公网链接则留"待发布后回填"占位。

最后一次性交付三样成品：.md 策划案、.html 网页、物料汇总文档（含独立 PNG）。

03三个 skill 逐个说明

SKILL 01

小测试制作

什么时候用：只需要策划方案，不急着做网页时。

必须给出的输入

  • 主题 / 选题
  • 目标人群
  • 规模档位（三选一，不给具体数字）
  • 风格偏好
  • 是否商用变现（决定去侵权强度）

规模档位（只有三档，结果数与题数 1:1）

档位正式题数结果数维度数每题选项每原型出现次数
轻量1212444 次
标准（默认）1818644 次
加大2424844 次

输出：固定八章（名称与顺序不可变）

  1. 产品定位
  2. 题目大纲
  3. 结果大纲
  4. 引流题
  5. 计分规则
  6. 视觉与文案规范
  7. 可以发小红书的物料
  8. 风险清单与上线检查
硬性规则（踩坑高发区）
  • 计分均衡：题数 × 每题选项数 = 结果数 × 每原型出现次数，且结果数必须能被 3 整除。不配平会导致某些结果永远抽不到。
  • 去侵权：真人姓名、节目/IP 名称一律换代号；不用真人照片、肖像、节目画面、logo。商用时为硬性要求。
  • 引流题只留题目本身：不加映射表、挑选标准、转化逻辑等分析内容。
  • 第八章是"物料"不是"标题列表"：按标题 / 副标题 / 正文 / 标签的小节结构写。
  • 用户给的引导语逐字保留：含 emoji、@账号、选项记录方式、评论区引导等，不要改写。

常见迭代指令

  • "结果大纲去掉代码列"
  • "引流题只留题目本身"
  • "正文改成约 200 字口语化种草文"

只改被点名的部分，其他不动。

SKILL 02

网页制作

什么时候用：已有策划案（或主题明确），要做出能直接运行的网页时。

必须给出的输入

  • 主题与规模档位
  • 口令（指定或随机，默认随机 4 位数）
  • 视觉调性（甜暖治愈 / 俏皮 / 文艺 / 简约）
  • 是否商用（商用需去侵权）

输出

单个 HTML 文件，HTML/CSS/JS 全部内嵌、零外部依赖、双击本地即可运行。

文件名规则（非常容易踩坑）
  • 用测试主题的拼音，如"恋人类型测评" → lianrenceping.html
  • 全小写、拼音连写、不带声调、不加空格或连字符、≤ 20 字符
  • 不能是汉字文件名，也不能用 index.html / index.htm
  • 禁止任何 http(s):// 外链、<link>、@import、src=、fetch(、XMLHttpRequest

六项硬性要求

  1. 口令门控默认必做：写死在代码里的固定数字（var PASSCODE="3167"），用 <input type="password">，不是随机图形验证码。位于首页之前、不可绕过。只有用户明确说"不要口令"才省略。
  2. 结果文案三段式：每结果约 250 字，「👀 一个画面（被说中）→ 🌱 这是这样的你（上升到性格）→ ✨ 一句话送给你（金句高亮）」。
  3. 结果可保存：提供"生成我的结果海报"按钮，Canvas 绘制 750×1500 竖版海报，支持长按保存 / 点击下载 PNG。
  4. 免责声明：结果页底部与海报底部都要有小字"本测试为趣味娱乐内容……不构成任何心理诊断或情感建议"。
  5. 浏览器实测：口令拦截 → 正确口令进入 → 答题 → 结果 → 生成海报 → 下载 PNG，全程跑通并抓 pageerror。
  6. 计分均衡校验：改一次题库就要重跑 scripts/verify_quiz.js。

交付时会告诉你：口令是多少、在代码第几行修改、文件名怎么来的。

SKILL 03

发布物料

什么时候用：网页已成型，要做上架和社媒素材时。

必须给出的输入

  • 主题与对外代号（去侵权后的称呼）
  • 公网答题链接（关键）
  • 引流题数量（默认 4 道）
  • 是否要 AI 插画背景（默认不要，走本地排版）
  • 物料范围（只要图片 / 只要文案 / 全套汇总）

输出顺序（固定）

主图封面
→
引流题卡片
→
社媒文案
→
发货文案
→
检查清单

外加一份汇总文档和全部独立高清 PNG 原图。

输出格式约定
  • 图片：固定 PNG。全部物料图片一律输出 PNG，尺寸 2160×2880（3:4），不输出 JPG / SVG 等其他格式。
  • 汇总文档：默认二选一。在线协作文档（腾讯文档）或 Word（.docx），按你当前可用的文档环境决定；未另行指定时不产出 Markdown / PDF 作为汇总主件。
  • 交付时同时给独立 PNG 原图，供单独取用。
硬性规则
  1. 链接前置、缺值才追问、不编造：发货文案里的链接必须是公网可直接打开答题的页面。本地文件路径、仓库源码页（blob 页）、未发布草稿都不能当发货链接。用户只说"有"却没贴网址，不算拿到链接，继续追问。
  2. 没有链接时的合法做法：用户明确说"还没有 / 稍后补"时，其余物料先做，链接和口令位置留"待发布后回填"占位。
  3. 默认本地排版不耗额度：图片用 HTML/CSS + 内联 SVG，脚本调系统 Edge 截图导出 PNG，不调用生图模型。要 AI 插画背景会先确认。
  4. 全套风格统一：主图与所有卡片共用同一套色板、字体层级、边框与装饰语言。
  5. 卡片尺寸：3:4 画布，1080×1440，导出 2 倍高清 PNG。
  6. 图片独立交付：文档内嵌位图双击不弹原图是正常行为，必须同时给独立 PNG 原图。

04完整实操流程：从想法到上架

  1. 对话输入想法

    说"做一整套 XX 测评"，触发总控。

  2. 拿到策划案 .md

    检查八章齐不齐、计分均衡、去侵权、题目是否场景化。不满意就增量修改："结果大纲去掉代码列"。

  3. 拿到网页 .html

    双击本地打开，输入口令，完整答一遍，生成海报并下载。检查口令、结果文案、海报有无溢出。

  4. 发布网页，拿到公网链接

    发货文案需要公网可直接打开答题的链接，本地 file:// 路径不能作为发货链接。拿到链接后进入下一步。

  5. 回到对话，提交链接

    "链接是 https://xxx/…，继续出物料"，发布物料 会用它写发货文案。

  6. 拿到物料全套

    汇总文档 + 独立 PNG，检查封面文字与文案一致、链接正确。

  7. 上架

    按"上线检查清单"逐项核对。

05常见问题与排错

说"做一整套"没触发总控，只触发了单个 skill？

检查话术里有没有"一整套 / 一条龙 / 全包了 / 从策划到上线"这类词。只说"做一个测试"偏向单个 skill。另外新装的 skill 要在新会话才会加载。

总控跑了，但三个 skill 反复问我同样的问题？

总控的 Step 0 已经收口需求，正常不会再问。如果遇到，直接回答并把答案说清楚，或明确讲"这些前面已给，直接执行"。

结果总是抽不到某几个？

计分不均衡。检查 题数 × 选项数 = 结果数 × 每原型出现次数，且结果数能被 3 整除。用 网页制作 skill 自带的 verify_quiz.js 校验。

物料文档里的图片双击不弹原图？

这是文档内嵌位图的通用行为，不是 bug。交付时已另给独立的高清 PNG 原图，用那些。

没有公网链接，能先出物料吗？

能。图片、社媒文案、商品详情都能先做，链接和发货文案留"待发布后回填"占位，拿到链接后再补。
